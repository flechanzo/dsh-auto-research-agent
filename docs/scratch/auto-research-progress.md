# Auto research workflow progress

This temporary page records the implementation checkpoints for the human-in-the-loop research workflow. Each checkpoint is committed and pushed to `flechanzo/dsh-auto-research-agent` before the next one starts.

## Current status

- **Clean repository baseline — complete.** The repository was reinitialized with a new `main` history and pushed to the project repository.
- **Research DAG model — complete for the first milestone.** `@deepseek-ai/dsh-workflow/research` now models stage outputs, immutable nodes, branch creation, history continuation, user decisions, feedback, and the explicit innovation-claim check.
- **Web workflow surface — complete for the first milestone.** The existing workflow UI now contributes an `Auto research workflow` action in the Session header and a right-Sidebar page with paper upload, stage output, confirmation, feedback, rejection branches, history navigation, reviewer roles, and simulation/final-plan choice.
- **Research panel visual refresh — complete for this checkpoint.** The panel now has a workflow identity header with stage and status pills; separate cards for the branch tree, conversation timeline, selected artifact, upload area, decisions, complete stage contents, and final plan. Buttons, inputs, and branch selectors reuse client design tokens with clearer keyboard focus and status colors, and narrow windows collapse to one column. The same treatment covers the header entry and message-tail branch action.
- **Host coordinator — second milestone complete.** `ResearchCoordinator` now advances only confirmed nodes, reads durable paper attachments, fetches explicit paper indexes through `ctx.web`, delegates summarization, problem extraction, idea generation, refinement, and parallel method/novelty/reproducibility reviews, preserves rejected ideas in isolated branches, and writes a branch-scoped Markdown plan through `ctx.fs` when assembled with `createHostResearchCoordinator()`.
- **Browser integration and resume — current milestone complete.** The Web panel now reads and writes the Session-scoped `research` Remote, uploads paper bytes through `ctx.fileUpload`, renders returned artifacts, persists a revision-checked DAG sidecar, and restores state after reload. Selecting a historical node can restore a new Session at its recorded event boundary; confirming the research direction runs a second targeted literature stage; and the final plan displays its Markdown plus the written file path. The Host and Client project graphs, generated Typert Remote artifacts, API Remote aggregation, and Web profile rows are wired. The local Web profile starts without a `research-controller` import warning.
- **Scanned PDF/OCR — complete for this checkpoint.** The Host reader uses PDF.js per page, keeps usable embedded pages, and treats missing or very short page text as incomplete. It renders at most the configured page count, scale, and pixel budget with native canvas, persists each PNG through `AttachmentStore`, and sends only missing or sparse pages to a visual OCR subagent. The returned document merges embedded and OCR pages in source order, records `plain-text`, `embedded-text`, or `ocr`, includes the inspected page count, preserves page markers, and reports `PDF_OCR_UNAVAILABLE`, `PDF_OCR_PARENT_REQUIRED`, `PDF_OCR_EMPTY`, or page-specific `PDF_OCR_FAILED` errors clearly.
- **Agent selector entry — current UI fix complete.** The new-session hero now labels the existing preset control as `Agent`, and the Web bundle ships an `Auto research agent` preset. Selecting it gives the agent the research workflow prompt and keeps paper upload, indexed-literature fetch, subagent, review, and plan tools available; the native DeepSeek `web_search` tool is disabled for this preset.
- **Explicit ML literature indexes and model routing — current checkpoint complete.** The automatic research workflow no longer calls the native DeepSeek Web Search operation. It queries only selected paper indexes through the fetch capability: arXiv ML categories, OpenReview proceedings such as ICLR/NeurIPS/ICML, Semantic Scholar, ACL Anthology, and OpenAlex. Each index can fail independently, results are de-duplicated, and the selected sources carry into the second targeted search. Every research and OCR child inherits the current conversation's provider, model, reasoning effort, and token limit; prompts require Simplified Chinese output while preserving titles, URLs, code, formulas, and JSON field names. After either literature-search checkpoint, users can upload supplemental papers and append their summaries to the same node history.
- **Multi-source innovation novelty screening — current checkpoint complete.** Before an idea reaches the user, the coordinator searches the selected paper indexes again with that candidate, combines the uploaded-paper summary with every initial, supplemental, and direction-targeted literature artifact, and gives only those evidence blocks to an isolated innovation reviewer. The reviewer compares mechanisms, modules, objectives, data, experiments, metrics, and contribution claims; missing candidate evidence, high overlap, or a score below the threshold discards the candidate and starts another attempt.
- **Same-panel interaction fixes — current checkpoint complete.** One file selection can upload several papers for one comparative reading stage. The right Sidebar displays the complete branch tree and expandable content for every stage, offers multi-select direction focus areas, and renders the final plan from the selected branch artifact after it is written. After Markdown writing, the main Chat and Sidebar retain every completed stage; the message-tail research branch action creates a DAG branch in the current Session instead of opening a new Conversation. Continuing from an earlier node keeps that node's memory, and both projections consume the same revision snapshot.
- **Per-Session project workspace — current checkpoint complete.** Each advancing research Session creates `research-projects/<sessionId>` below its Session cwd through the injected filesystem. `research-conversation.md` and `research-state.json` keep the visible DAG and final plan output in that directory, while later stage writes preserve the uploaded-paper list and the configured `planPath` stays inside the project.
- **Sandbox-safe project writes — current checkpoint complete.** Project records and final Markdown writes now carry the resolved Session sandbox policy. The controller falls back to the root Context provider when an Agent scope does not inherit the service, preventing a false file-access denial during upload or final output under `workspace-write`.
- **Synchronized main conversation — current checkpoint complete.** The main Chat view renders every research stage message from the same revision-ordered store as the right Sidebar. The Conversation/Trajectory tab strip selects branches in the same Session, node clicks synchronize both regions, and historical selections keep later branch nodes in the graph without mixing them into the selected memory path.
- **Research Sidebar registration — current checkpoint complete.** The workflow now waits for the right Sidebar, research Remote, and upload services before registering its tab type, body, title, header action, and workflow-node slots. Every registration is reversible, and stable task/node markers expose the selected node, active branch, task artifact title, and complete lineage in the same panel.
- **Multi-question extraction — current checkpoint complete.** Problem extraction asks for every distinct testable question and gap in numbered form, keeps separate answers separate, and ends with a synthesis for downstream literature search and idea generation.
